# Tetris development feedback

Author: AI developer, requested by the project owner. Engine baseline: `b2d559b43217e66474f4120a6e72b783961c7732`. Game: `games/tetris`.

## Retain the shared lifecycle

The portable two-d starter supplied rendering-free fixed-step simulation, deterministic replay and exact snapshot continuation without a custom runtime. Shared focus, input accumulation, saves, settings, pause, native resources, fullscreen and package verification substantially reduced game-specific code. Its existing centered, text-only BlueEngine Games startup meets the current branding preference; a second game-owned card is unnecessary.

## Prioritized improvements

1. **Named input command edges in portable games.** `Intent` has axes and one action boolean. This puzzle needs clockwise/counterclockwise rotation, hold, hard drop and three mode commands. The public `device_input` hook works, and `pointer_target_only_on_press` preserves a command across frames without a simulation tick. The game currently carries command IDs through sentinel pointer coordinates. Add an optional command bitmask/typed edge channel to Intent and its accumulator, preserving the existing action API, replay, snapshots and native controller mapping. Reproduce by implementing hold and reverse rotation alongside hard drop in a two-d starter. Regression cases should include two device frames before a tick, multiple catch-up ticks, simultaneous commands and focus loss. See learning record L-315.

2. **Authored named one-shot sounds in the shared 2D client.** `take_cues()` selects fixed Coin, Hit and Success sounds. `AudioBankSpec` supports authored looping music but rejects effects in that bank. The result is a polished original music bed but generic lock/clear feedback. Provide an optional named effect bank and cue mapping while preserving shared mute, pause, asynchronous loading and error reporting. Keep the existing three cues as defaults. A minimal reproduction is a portable game requiring separate rotate, hold, lock and four-row-clear sounds. Do not infer audible hardware success from decode/playback submission counters. See L-316.

3. **Audio render directory prerequisite in the quickstart.** A fresh scaffold has no `assets/audio`. `audio render SOURCE assets/audio/pulse` reports `bundle parent directory must exist`. Creating the parent fixes the failure. Document the mkdir step or create only the missing parent while retaining exclusive new-bundle creation and completed-output preservation. See L-317.

## Evidence and limitations

Rule tests cover bag distribution, both rotation directions, wall/floor kicks, hard/soft drops, hold limits, top-out, line-clear animation, back-to-back scoring, T-spin detection, lock delay, mode completion and exact save continuation. The public route exercises gameplay without direct state changes. Native landscape and 480x900 portrait captures were inspected for the requested centered board, two tiny next-piece hints, visible spawns and ghost placement. Gameplay statistics and control lists are confined to pause/results or the guide. Original two-layer PCM music passes the audio loop report with no clipping, DC or click issues. Clippy passes with warnings denied.

The gallery is software-rendered native gameplay, not concept art. Synthetic X11 key events are an additional native device-path probe and do not certify physical controllers. Physical audio output remains unverified. Linux package smoke and Windows installer CI are separate delivery gates; publication must retain their exact-source receipts. The release journal records final CI and downloaded-file checksums rather than treating this note as gate evidence.

The requested portrait layout also exposed a presentation gap: the shared client fixes its logical canvas to 800x450. The game inverse-maps native window dimensions into Scene coordinates to fill portrait letterbox margins while retaining shared timing/input/storage. Add optional game-owned logical dimensions or a responsive viewport contract, and a game-owned default window/fullscreen preference. Keep existing 800x450 consumers unchanged.

## Improvements implemented while satisfying the controller request

The portable client previously consumed only left-stick axes and South; D-pad,
Start and Select were ignored. Added D-pad axes with digital priority, Start
start/pause/resume and Select retry. A backward-compatible `Game::gamepad_input`
hook lets games map positional buttons using the existing once-per-frame backend
and shared focus/accumulation lifecycle. Tetris supplies clockwise/reverse, hold,
hard drop and mode-cycle mappings. Regression tests cover digital axes against
stick drift, opposing directions and gameplay command behavior. Hardware
compatibility still depends on mapped native drivers and has not been attested.

Added `Game::default_fullscreen()` (default true) so Tetris can launch in a tight
portrait window without overriding explicit flags or saved preferences. The
final playfield returns to the classic 10x20 grid, with two readable next-piece previews after visual review.
Responsive logical dimensions remain a future improvement.

## Native icon gate

A code-native tile icon initially passed basic decode but failed shipping because
it omitted native shell sizes, used PNG for the 16-pixel frame, and lacked
transparent corners and sufficient shades. The package gate correctly preserved
the completed package and isolated render. `scripts/make_icon.py` now regenerates
the same original tetromino artwork at all ten required sizes, with 32-bit BGRA
DIB/AND-mask frames below 64 pixels, RGBA PNGs from 64 pixels, matching raw window
blobs, transparent rounded corners and shaded tiles. Direct icon-file/art checks
pass. An early standalone asset-preflight command would catch these requirements
before compiling a complete native package; retain the existing shipping check.

Portrait package smoke passed, but publication additionally requires a landscape
capture from that isolated package. Declaring explicit landscape `smoke_args` in
identity keeps the player's tight portrait default and supplies the download-site
evidence. Document this cross-gate requirement in the portrait-game quickstart or
let the release supervisor request its own landscape capture from the checked
package; do not make the author change the player's preferred window shape.
