# Sway: native music visualizer feedback

Sway imports local media through a multi-select file dialog or Windows file
drops. Rodio streams decoded samples unchanged to playback; a bounded PCM tap
provides a real spectrum, waveform, energy and onset envelope. BlueEngine owns
the shared fixed-step variation state, snapshot contract, viewport and Scene
composition. Six visual families, six palettes and automatic seeded chapters
make each listen different. Space pauses sound, animation and the ten-second
title together. The published target is Windows x64.

## Changes made while building it

- Added `two-d-draw`, a graphics-only feature. Previously every 2D client pulled
  in Macroquad audio. A custom streaming player then failed Cargo resolution:
  Macroquad/quad-snd and Rodio/CPAL depended on incompatible crates with the
  same `links = "alsa"`. Existing `two-d`, `portable`, `presentation` and
  `client` still enable their usual audio. The new feature exposes the existing
  draw facade without creating another renderer.
- Added a Windows path-only file-drop adapter in
  [dropfiles.rs](../../games/sway/src/dropfiles.rs). The pinned Miniquad 0.4.8
  `WM_DROPFILES` handler reads whole files into memory and never dispatches
  `files_dropped_event`; Macroquad therefore exposes no dropped files there.
  It also uses a fixed `MAX_PATH` buffer. Sway uses dynamically sized UTF-16
  paths, releases the drop handle, queues paths, and decodes off the UI thread.
- Added native control evidence, including real Windows `WM_DROPFILES`
  messages for one file and multiple files, filenames with Unicode/spaces,
  and pause/resume keys. Paused PCM position, variation state, title clock and
  captured PNG bytes must remain identical. This runs after the Windows
  isolated packaged-game smoke, with a pinned Mesa dependency outside the
  shipped product.

## Engine improvements worth carrying forward

1. **Repair native file-drop delivery in the rendering backend.** Dispatch the
   event, preserve Unicode/long paths, release native ownership, and offer a
   paths-only API. Eagerly copying a large playlist defeats streaming. Linux
   X11 and Wayland also need URI-list parsing: strip `file://`, decode percent
   escapes and reject nonlocal hosts. Their raw URI strings currently fail
   filesystem reads. Sway does not advertise Linux as a distribution target.
2. **Offer a streaming media client adapter.** The engine audio bank works for
   authored game cues; user-selected, long audio files need a decoder, queue,
   errors, end-of-track handling and pause-aware playback position. Keep these
   client responsibilities outside rendering-free simulation. A small PCM tap
   and timestamped, bounded analysis queue would avoid repeating this work in
   future music tools.
3. **Include native input evidence in shipping helpers.** A screenshot smoke
   proves drawing, but would miss this file-drop failure. Reusable key/drop
   injection and synchronized audio-clock assertions would strengthen releases.
   Emulated audio and software rendering still do not prove listening through
   a physical speaker or performance on every GPU.

## Observed verification

The decoder/FFT tests use actual PCM: silence, a known-frequency sine, stereo
anti-phase content and a real WAV. They check unchanged output samples and
bounded history. Simulation tests verify deterministic restore, fresh seeds
for repeat listens, different track identities and title expiry.

The Linux native key test passed, including byte-identical paused pictures,
unchanged audio position/title timer and simultaneous resume. Native frames on
the Intel N97 software renderer at 1280x720 measured the following after a
one-second warmup; each style ran for three seconds, without frame recording:

| Style | Mean frames/s | 95th-percentile frame interval |
| --- | ---: | ---: |
| Orbit | 125.46 | 8.41 ms |
| Silk | 115.56 | 9.35 ms |
| Prism | 132.11 | 7.71 ms |
| Bloom | 96.95 | 14.05 ms |
| Stardust | 147.76 | 7.10 ms |
| Tide | 105.40 | 12.03 ms |

These are actual frame intervals, not a video's nominal frame rate or an
offscreen render estimate. The lighter batched geometry avoids the fullscreen
fragment workload that limited the earlier Wormhole software-rendered preview.
Measurements describe this test setup, not a universal hardware guarantee.
