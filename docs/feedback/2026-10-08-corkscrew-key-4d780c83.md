# Corkscrew Key: AI development feedback

Run: `4d780c83`.
Project: `games/corkscrew-key`. State: published.

## Generated mechanic

Every quarter-turn of your floating, asymmetric key also advances it exactly one grid unit along the axis of rotation. You cannot translate without turning or turn without translating. Surprisingly, a closed movement loop can return the key to its original position with a different orientation.

## Novelty and playtesting

The closest comparison is Interlocked's manipulation of blocks in three dimensions, with separate viewing and pulling controls. [Interlocked description](https://www.gpstudios.com/games/view/interlocked). Corkscrew Key instead binds an object's rotation and translation into one signed action; returning to the same position can change its orientation. Among the supplied mechanics, Rotation Relay also uses rotation, but spends stolen angular velocity to turn an arena and redirect gravity. This concept changes only the key's pose, with no borrowed resource, gravity change, gap exchange or perspective scaling. Worldwide originality and fun remain unverified.

Players may struggle to predict rotation direction, or find swept collisions stricter than the destination suggests. Fixed axis labels, full-path previews and unlimited undo are essential. The prototype should demonstrate that spatial discoveries drive play rather than repeated trial moves; overly narrow passages could otherwise reduce every turn to checking the preview.

## Findings from the AI that developed and reviewed the game

### 1. input (medium)

Observed: The shared native client exposed movement and primary action, but no mapping hook for number keys, undo, right-drag or scroll. Implementing the requested controls required reading client source.

Reproduce: Implement the concept's controls using the three-d starter and shared client.

Workaround: Added a backward-compatible device_input hook, retained-command regression test and public documentation. Gameplay still changes through fixed-step Intent input.

Proposed engine improvement: Retain the hook and provide a documented spatial-puzzle input example.

### 2. tooling (low)

Observed: Scaffolding with the checkout-root engine argument '.' wrote dependency path='.' into the game's Cargo.toml, pointing at the game itself.

Reproduce: Run map new-game with a nested game directory and '.' as ENGINE_PATH.

Workaround: Changed the generated dependency path to '../..'.

Proposed engine improvement: Resolve the engine argument before generating a path relative to the game directory, and reject self dependencies.

### 3. workflow (medium)

Observed: The full engine check passed 610 Rust tests but failed 13 localhost networking tests with socket PermissionDenied. The Python server-load fixture also failed on denied sockets.

Reproduce: Run be2.py check --changed in this restricted environment.

Workaround: Preserved the failed report and separately passed affected input tests, Clippy, rustdoc, game checks and the headless boundary check.

Proposed engine improvement: Detect socket restrictions before running network fixtures and classify these failures as environment blocks.

### 4. platform (medium)

Observed: Virtual-display launches intermittently failed with XOpenDisplay errors. Debug replay captures succeeded, but isolated package smoke and the complete live-input route could not be certified.

Reproduce: Run ship --no-install or the isolated native launcher on this host.

Workaround: Inspected successful native captures, exercised Space/Z/K/L in a real window, verified package integrity separately and documented remaining gates.

Proposed engine improvement: Provide a canonical native input probe with reliable virtual-display startup and captured state assertions.

### 5. process (medium)

Observed: The separate live-control screenshots are black and cannot substantiate the recorded manual-input claims. Successful package replay demonstrates simulation behavior but bypasses physical keyboard and mouse mapping.

Reproduce: Inspect the native-controls PNGs and associated launch logs; failed launches include unavailable-display and existing-capture-directory errors.

Workaround: Use the successful isolated package captures for visual evidence and behavioral tests for rule evidence.

Proposed engine improvement: Repeat keyboard, clickable controls, orbit, zoom, pause, retry and save/load on a working display with fresh, nonblank captures. Update STATUS.md to distinguish supported evidence from failed attempts.

### 6. ui (low)

Observed: A docked chamber still computes the selected movement preview and colors its obstruction red even though Space now advances chambers. This appears in the solved beam-chamber capture.

Reproduce: Dock beneath the beam with a selected next screw step that would collide; observe SOCKET MATCHED alongside the red beam.

Workaround: Follow SOCKET MATCHED and SPACE NEXT.

Proposed engine improvement: Suppress movement obstruction coloring while docked.

### 7. audio (medium)

Observed: Genuine engine/backend friction: the successful isolated Linux smoke logs an ALSA audio-thread panic while graphics and completion continue. Audible playback is unverified.

Reproduce: Launch the native package on a Linux audio backend that rejects the requested sample rate.

Workaround: Use a working audio configuration and retain stderr separately from visual success.

Proposed engine improvement: Make backend initialization failure recoverable and expose unavailable audio clearly instead of leaving a panicked worker thread.

### 8. input (low)

Observed: Genuine engine authoring friction, addressed here: custom axis/sign/undo keys required extending the shared client with Game::device_input and preserving mapped command targets across frames without simulation ticks.

Reproduce: Implement these custom keyboard commands using the previous shared client's fixed input mapping.

Workaround: Use the documented device_input hook to emit public Intent commands.

Proposed engine improvement: Preserve the hook and retained-command regression coverage through subsequent engine CI.
