# Embertrail

Start/resume from the configured engine checkout with `python3 tools/be2.py start "<task>" --project GAME_DIR --compact`. Read this file, `src/lib.rs`, `src/main.rs`, and `game.project.json`.

- `GameLogic` + `Simulation` own fixed 60 Hz integer rules. Draw reads state. Gameplay input is `Intent`; action is the one jump, secondary casts. Never make Up/W a second jump.
- This game uses a custom client (`src/game_client.rs`) built on engine devices, timing, Scene rendering and PlatformStorage. It owns controller menu navigation, pause/retry/quit, settings, and contextual audio. `src/window_focus.rs` detects desktop focus.
- Saves use the engine's frame/hash/migration contract. Keep KIND stable, bump VERSION for released state changes and test real framed migration. Version 4 adds stair travel and input/boss latches, preserving version 3 state with collision recovery for previously embedded positions. Earlier migration preserves version 2 surface/campaign state while replacing its old underground room; version 1 restarts the loaded course at its entrance.
- `src/story.rs` provides automatic brief NPC greetings, guardian names and bell milestones. There are no dialogue choices. Mote must recover the village's Dawnheart from Vesper before home freezes.
- Keep the clear side profile of Mote and the collar recovery marker readable. Derive parallax scenery from world-cell identity before camera projection. Anchor ground detail to world coordinates.
- Use the bundled licensed sans font, readable HUD/menu sizes, and high contrast. Measure the actual shared Font for wrapping, ascent and overflow inside padded bounds. Pixel artwork does not imply a pixel body font. Inspect long real strings at 960x540 and 1280x720. Keep Controls in its optional menu screen; no permanent controls strip.
- Score identity comes from `assets/audio/score/tracks.json`. Pause displays/downloads the actual current composition, even while another loads. Validate bundle checksums; do not equate counters with audible hardware playback.
- Prepare only the current course's world/grotto/applicable boss score during a loading transition. Keep at most four unique decoded music handles including outgoing fades. Never decode music or first-use sprites in active play: Macroquad's async WAV wrapper performs synchronous decoding. Prewarm the small sprite set and common glyph sizes using the same caches the renderer reads. Use `--profile-frames` without capture and an isolated data directory when measuring autosaves.
- `src/cues.rs` names semantic events; `assets/audio/sfx` has bounded, varied interaction sounds. Do not reuse a collection cue for unrelated events. Preserve cooldowns, priority and the four-voice budget. Shut down native sound and cached GPU resources while the window context is alive.
- Grottos have eight regional mechanical archetypes and four variants each. Keep actual platforms, springs, hazards, pickups and exits consistent with art. Ordinary traction applies underground, including Frostbloom's warm rooms.
- Sweep rider carry against static solids before changing coordinates. A collision sweep does not reliably repair a body already embedded by direct position changes. Horizontal platforms slide beneath blocked riders; upward lifts hold their phase when ceiling clearance blocks the rider. Retain authored obstruction and escape regressions.
- Stairs use the authoritative 40-step transition; draw reads its elapsed/direction/gate. Freeze world time and input motion during travel, hide the midpoint swap, and require a fresh Down press to enter again. Test framed saves throughout both directions. Never animate travel by moving authoritative state from draw.
- Boss music starts at actual first visibility, latches through offscreen attacks and pause/Atlas, and ends on defeat/death/course change. Keep the five modest battle arrangements named/downloadable and their transitions prepared; never infer first visibility solely from the boss AI phase.
- Regenerate assets with `scripts/make_world_art.py`, `scripts/compose_soundtrack.py`, and `scripts/compose_interactions.py`. The obsolete `make_art.py` combines old sprites and short stems and must not overwrite this update.
- `verification_input` and development route probes use public intentions. Do not mutate the game to pass verification. Capture-only showcase fixtures are presentation evidence, explicitly excluded from gameplay verification.

Run `cargo test --locked` and appropriate Clippy checks. From the engine use `be2.py check --game GAME_DIR --loop inner`, then integration and shipping. See `examples/README.md` for bounded traversal search and independent replay.

Windows distribution uses `python scripts/ship.py ship`, Inno Setup 6, and `scripts/test-installer.ps1`. Publish only a Windows x64 installer after its native workflow passes. Keep player saves/settings outside the install directory. Compilation, software captures, and audio submissions do not certify physical controller or speaker review.

Delivery of a requested verified update includes publishing the versioned Windows installer in the established Embertrail release repository, updating its BlueEngineGames listing/history and screenshot, and verifying the successful Pages deployment and live download. The player explicitly expects this automatically unless they request local-only work; do not stop at a local candidate or ask for routine publication confirmation. Preserve previous releases and publish the exact verified bytes with their public source and checksum.
